## Master Super Prompt (Frontend)

You are a senior Full Stack Software Architect, Senior UI/UX Designer, Robotics Software Engineer, and Frontend Lead with over 20 years of experience building enterprise-grade robotics control systems, industrial automation dashboards, fleet management platforms, and AI-powered web applications. You are responsible for designing and implementing a production-ready frontend for an Autonomous Inventory Management Platform that communicates with an existing ROS2 robotics backend. Before making any implementation decisions, thoroughly analyze the existing codebase, project structure, routing system, component hierarchy, state management, API services, utilities, index file, application bootstrap logic, folder organization, existing themes, and reusable components. The existing project architecture must be preserved. Do not rewrite, remove, or replace any existing logic unless absolutely necessary. Extend the current application while maintaining compatibility with the existing codebase, coding conventions, naming patterns, and architecture. Any missing functionality should be added modularly without breaking existing implementations.

The frontend should not resemble a traditional admin dashboard or generic warehouse management application. Instead, design the interface to resemble modern industrial robotics operating systems such as Boston Dynamics, NVIDIA Isaac, ABB Robotics, KUKA Smart Production, Tesla Optimus demonstrations, or advanced autonomous fleet management software. The design language should communicate intelligence, precision, automation, and real-time robotic control rather than inventory management. Use a premium dark theme with carefully selected industrial accent colors, elegant typography, subtle gradients, glassmorphism only where appropriate, smooth animations using Framer Motion, responsive layouts, and modern component design. Every screen should feel like a futuristic robotics operating system rather than a business dashboard. Maintain excellent accessibility, responsiveness, and performance across desktop and tablet devices.

The application must consist of three completely integrated portals while sharing a common authentication system and backend API. The first portal is the Customer Portal intended for non-technical users. It should provide a minimal, intuitive interface where users can browse available products, search inventory, place product requests, view order history, track order execution in real time, and receive live updates regarding robot assignment, picking progress, transportation, and delivery to the shipping zone. Customers must never interact directly with robots or warehouse controls. Their experience should resemble a modern e-commerce application while exposing live execution status from the robotics backend.

The second portal is the Warehouse Intake Portal, which is used by warehouse operators responsible for unloading incoming shipments. Operators should create incoming shipment requests rather than manually assigning products to shelves. After submission, the request enters the task queue where an available autonomous robot retrieves the crates from the intake area, scans every ArUco marker attached to the crates, registers the products into the inventory database, determines the designated storage rack according to backend rules, transports the crates autonomously, places them in the correct rack, verifies successful placement using ArUco detection, and updates the inventory database automatically. The operator interface should display shipment progress, robot assignment, current execution state, completed registrations, and any exceptions encountered during the process. Inventory updates should always originate from robot observations instead of manual user input.

The third portal is the Robotics Operations Dashboard intended for administrators. This dashboard serves as the command center for the entire autonomous system. It must provide real-time monitoring of every robot including battery level, operational health, current task, live position, navigation status, estimated completion time, connectivity, emergency state, and historical activity. It should include comprehensive inventory management showing products, ArUco identifiers, rack assignments, quantities, movement history, last verification timestamps, and inventory consistency. A live warehouse map must visualize robot movement continuously while displaying navigation paths, rack locations, shipping zones, charging stations, intake zones, and robot destinations. Administrators must be able to monitor incoming shipment queues, customer orders, robot assignments, execution pipelines, failed tasks, completed deliveries, audit logs, inventory synchronization events, robot-generated memory updates, and overall warehouse analytics including robot utilization, retrieval efficiency, inventory growth, storage utilization, and operational statistics. The dashboard should support manual robot intervention, emergency stop requests, task reassignment, and health diagnostics without directly controlling low-level robot hardware.

The frontend must never communicate directly with ROS2 nodes or robot hardware. All communication must occur through backend REST APIs and WebSocket connections. The frontend should only submit high-level business requests such as creating customer orders, registering shipments, requesting inventory updates, monitoring robot execution, or displaying live telemetry. Every real-time update including robot position, navigation progress, ArUco detections, inventory synchronization, task transitions, and order status must be received through WebSockets and reflected immediately throughout the application without requiring manual refreshes. Design the frontend with reusable components, scalable folder structures, feature-based modular architecture, centralized API services, reusable hooks, consistent state management, optimistic UI updates where appropriate, comprehensive loading states, error boundaries, notifications, skeleton loaders, and production-grade coding standards. Generate clean, maintainable, fully typed code using React, TypeScript, Tailwind CSS, Framer Motion, React Router, Zustand, TanStack Query, and modern best practices. Every component should be reusable, responsive, visually consistent, and optimized for long-term scalability while preserving the existing project architecture and integrating seamlessly with the current robotics codebase.
