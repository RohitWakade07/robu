# Master Super Prompt - Agile Methodology for Autonomous Inventory Management Platform

You are an experienced Agile Coach, Scrum Master, Product Owner, Enterprise Software Architect, Robotics Systems Engineer, and Technical Project Manager with over 20 years of experience managing large-scale robotics, AI, industrial automation, autonomous systems, warehouse management platforms, ROS2 applications, and enterprise software products. Your responsibility is to create a complete Agile Software Development Methodology tailored specifically for our project rather than generating a generic Scrum document. Before creating the methodology, carefully understand the complete product vision, software architecture, robotics workflow, existing ROS2 implementation, technology stack, project constraints, business goals, future scalability, and engineering priorities. Every recommendation must directly support the successful development of our autonomous warehouse platform.

The project being developed is an Autonomous Inventory Management Platform integrated with an existing ROS2 robotics system. The robot is responsible for autonomous navigation, ArUco marker detection, inventory registration, crate transportation, rack placement, retrieval operations, and warehouse patrol. The backend serves only as the orchestration layer responsible for authentication, warehouse memory, inventory management, robot fleet management, task scheduling, analytics, notifications, audit logs, and synchronization between the robot and the database. The frontend consists of three independent but interconnected portals including a Customer Portal for product requests, a Warehouse Intake Portal for registering incoming shipments, and a Robotics Operations Dashboard for monitoring robots, inventory, warehouse activity, analytics, and live robot telemetry. All communication between the software platform and the robot occurs through high-level task orchestration while ROS2 remains responsible for navigation and execution. Inventory updates originate from robot observations through ArUco marker detection rather than manual inventory editing.

Design a complete Agile methodology suitable for a multidisciplinary robotics software team consisting of frontend developers, backend developers, robotics engineers, embedded engineers, AI engineers, DevOps engineers, QA engineers, UI/UX designers, and product stakeholders. Recommend the most suitable Agile framework while explaining why it is appropriate for robotics software development where hardware, embedded systems, backend services, and frontend applications evolve simultaneously. If necessary, propose a hybrid Scrum-Kanban workflow to accommodate continuous robot testing, hardware integration, simulation, and software development.

Create the complete Product Vision, Product Goal, Product Roadmap, Release Roadmap, and Product Backlog. Divide the project into Epics representing major business capabilities including Authentication and User Management, Customer Ordering System, Warehouse Intake Management, Robotics Fleet Management, Warehouse Memory, Inventory Management, Robot Task Scheduling, ROS2 Integration, Live Robot Tracking, WebSocket Communication, Analytics Dashboard, Notifications, Warehouse Mapping, System Administration, Security, Monitoring, Reporting, Testing, Deployment, and Future AI Features. Break every Epic into Features, every Feature into User Stories, and every User Story into detailed Development Tasks following INVEST principles. Each User Story must include business value, acceptance criteria, priority, estimated story points, technical dependencies, definition of ready, and definition of done.

Generate a Sprint Planning strategy covering the entire project lifecycle. Organize the development into multiple iterative sprints that gradually transform the system from architecture setup to production deployment. Begin with project initialization, repository setup, coding standards, CI/CD pipeline, Docker environment, PostgreSQL database, FastAPI backend, React frontend, authentication, and ROS2 communication. Continue with inventory management, warehouse memory, robot task orchestration, order management, shipment processing, fleet management, analytics, notifications, reporting, security, performance optimization, testing, and production deployment. Every sprint should include Sprint Goal, Sprint Backlog, Development Tasks, Expected Deliverables, Acceptance Criteria, Risks, Dependencies, Review Demonstration, and Retrospective Objectives.

Design a dedicated Agile workflow for robotics development. Separate software-only tasks from hardware-dependent tasks. Define how simulation using Gazebo and ROS2 should be integrated into sprint planning before physical robot deployment. Include hardware validation checkpoints, integration testing, regression testing, warehouse simulation testing, navigation verification, ArUco verification, robot safety validation, communication testing, and deployment readiness reviews. Explain how robotics engineers and software developers synchronize their work using shared sprint objectives while minimizing hardware bottlenecks.

Define the complete Scrum ceremonies for this project including Sprint Planning, Daily Standups, Backlog Refinement, Sprint Review, Sprint Retrospective, Technical Design Review, Robotics Integration Review, Release Planning, and Architecture Review. Explain the objective, participants, inputs, outputs, expected duration, and artifacts generated from each ceremony. Include separate technical review meetings specifically for robotics integration, database evolution, API compatibility, and frontend consistency.

Develop a complete Definition of Ready and Definition of Done specifically for robotics software development. A user story should not begin implementation until requirements, UI wireframes, API contracts, database schema changes, robot interfaces, acceptance criteria, testing strategy, and technical dependencies have been approved. A user story should only be considered complete after code review, unit testing, integration testing, API validation, UI validation, ROS2 integration testing, warehouse simulation testing, documentation updates, deployment verification, and stakeholder approval have been successfully completed.

Create a comprehensive project risk management strategy identifying software risks, hardware risks, robotics risks, communication failures, database synchronization issues, WebSocket reliability, inventory inconsistencies, robot navigation failures, ArUco detection errors, deployment challenges, and security vulnerabilities. For every identified risk, provide probability, impact, mitigation strategy, contingency plan, monitoring metrics, and ownership.

Generate a quality assurance methodology covering frontend testing, backend testing, robotics testing, API validation, database testing, integration testing, WebSocket testing, performance testing, load testing, security testing, ROS2 simulation testing, hardware-in-the-loop testing, user acceptance testing, and production verification. Define measurable quality metrics, code coverage expectations, response time targets, deployment reliability, robot task success rates, inventory accuracy targets, and operational KPIs.

Produce a complete project documentation strategy identifying all technical documentation that should be maintained throughout development including Software Requirement Specification, Software Design Document, System Architecture Document, Database Design Document, API Documentation, ROS2 Integration Guide, Deployment Guide, User Manual, Administrator Manual, Warehouse Operations Manual, Testing Documentation, Sprint Reports, Release Notes, Technical Decision Records, and Future Enhancement Roadmap.

Finally, generate a detailed implementation timeline covering every sprint from project initiation through production release. Include milestones, sprint objectives, expected outputs, dependency mapping, parallel workstreams, resource allocation, estimated duration, review checkpoints, release candidates, production readiness criteria, and post-release maintenance strategy. The resulting Agile methodology should serve as the complete execution blueprint for building our Autonomous Inventory Management Platform from initial planning to production deployment while remaining scalable for future AI-driven warehouse automation, multi-robot coordination, cloud synchronization, predictive analytics, and enterprise expansion.
